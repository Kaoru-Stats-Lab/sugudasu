# 2026-08-14 — カタログ線引き（漢字拡大を材料にした憲法判断）

**判例:** [CASE-2026-009](../CASE_LAW.md#case-2026-009)  
**原料（DD・議論メモ）:** [`2026-08-14_kanji-magnifier_source.md`](./2026-08-14_kanji-magnifier_source.md)  
**決定:** 漢字拡大は **Reject**。Hub Value は採用の主因にしない。Adjacent は同一仕事系列のみ。端末は採用・排除の主軸にしない。

## この会議で決めなかったこと

漢字拡大の実装・SEO 実測・ユーザー5問インタビュー。判決に不要（同一 JTBD の無料代替が既にあることが主因）。

## 採った線（3）

1. Direct は再訪インフラとして Keep。「困ったらまず SUGUDASU」という習慣化は存在様式と衝突し、採用理由にしない。  
2. 横連携は既存コア仕事の直前・直後に限る。生活・学習・汎用変換は Hub Value だけでは GO にしない。  
3. 端末は identity ではない。割り勘のように Pain がスマホで起きても、ブラウザ完結・PC でも終わるならコア可。Hub のモバイルファースト化とネイティブ必須は不可。

## 初日案から直した点

「スマホ主戦場の仕事はコアに置かない」は **否決**。Brand Constitution に端末条項は無く、割り勘が反例。PC 原則はネイティブ必須と Hub のスマホアプリ化を防ぐ実装制約であり、Operate の発生場所の禁止ではない。

## 既存判例との関係

- CASE-2026-006（present）: Domain 外の提案型。本件事は Domain に乗っても **作る意味がない** 類型。  
- 2026-08-13 `reverse` Reject: コモディティ辞書。漢字拡大は同型（検索・既存サイトで足りる）。Hub Value で覆さない。

## 憲法本文

改正しない。Product Constitution の「横連携として採否」「PCブラウザで成立」の運用を判例と1段落で固定する。
