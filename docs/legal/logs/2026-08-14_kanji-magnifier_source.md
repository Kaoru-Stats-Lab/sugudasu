# 漢字拡大｜SUGUDASU新規ツール案 デューデリジェンス評価

## 1. Executive Verdict

**Reject**

理由（5行以内）：
- 同一JTBD（紙に書く直前に漢字を大きく確認する）を満たす無料Webツールが、機能・訴求文言までほぼ同一の形で既に複数存在する（ベンリーツール「漢字拡大ツール」、お便利ツール.com「漢字拡大ツール」、ラッコ手帳「漢字拡大ツール」等）それらは既にログイン不要でブラウザ完結、入力文字をサーバーへ送信しない設計を掲げている [Apple App Store](https://apps.apple.com/jp/app/%E6%BC%A2%E5%AD%97%E6%8B%A1%E5%A4%A7%E3%83%AB%E3%83%BC%E3%83%9A-%E6%BC%A2%E5%AD%97%E6%9B%B8%E3%81%8D%E6%96%B9-%E6%9B%B8%E3%81%8D%E9%A0%86%E6%A4%9C%E7%B4%A2%E3%82%A2%E3%83%97%E3%83%AA/id1329460323) 。
- ネイティブアプリ側にはさらに強い競合が存在し、巨大表示・なぞり書き・書き順表示を無料で提供するアプリ [App-ranking](https://www.app-ranking.net/id/1329460323) が高評価でストア上に定着している。
- 「大きく表示するだけ」はSUGUDASUの新規カタログでも既存Web競合との機能差がほぼゼロで、SEOでも後発不利。
- スマホ例外を許容してまで新規参入する必然性を正当化できるだけの差別化要素が見当たらない。
- カタログに置く価値より「車輪の再発明」のリスクの方が大きい。

---

## 2. 最大の賛成論

1. JTBD自体は本物。利用者は漢字の書き方が分からない瞬間にすぐ調べたいという明確な即時ニーズを持っている [APPLION](https://applion.jp/android/app/jp.flipout.kanjikakudai/) 。
2. 実装コストは低く、フォント表示＋SVG書き順程度ならSUGUDASUの標準的な工数で作れる。
3. 「登録不要・データ送信なし」という訴求は、広告だらけの既存アプリ（起動時に全画面広告が出て閉じるボタンが分かりにくいという不満がある [Andbrowser](http://andbrowser.com/kanji/) ）に対する広告体験面での差別化材料にはなり得る。

---

## 3. 最大の反対論

1. **機能的に完全に代替可能**：既に「ログイン不要・ブラウザ完結・サーバー送信なし・PC横書き/スマホ縦書き自動切替・スライダーでサイズ変更」という、この提案の想定MVPとほぼ一致するWebツールが少なくとも3サイト存在する（画数の多い難読漢字や旧字体の字形確認を目的に、文字を大きなフォントで表示するツールとして既に稼働している） [Digital Marketing](https://digital-marketing.jp/seo/how-to-find-a-search-volume-suggestion-word/)  [Apple App Store](https://apps.apple.com/jp/app/%E6%BC%A2%E5%AD%97%E6%8B%A1%E5%A4%A7%E3%83%AB%E3%83%BC%E3%83%9A-%E6%BC%A2%E5%AD%97%E6%9B%B8%E3%81%8D%E6%96%B9-%E6%9B%B8%E3%81%8D%E9%A0%86%E6%A4%9C%E7%B4%A2%E3%82%A2%E3%83%97%E3%83%AA/id1329460323) 。SUGUDASUが同じものを作っても「もう一つの類似ツール」にしかならない。
2. **アプリ側の競合が機能・体験ともに上回る**：拡大表示に加え指でのなぞり書きや書き順の逐次表示に対応したアプリ [App-ranking](https://www.app-ranking.net/id/1329460323) が既にストアで多数のレビューを獲得しており、片手操作や履歴保存、フォント変更機能まで持つアプリ [Oh-benri-tools](https://www.oh-benri-tools.com/tools/misc/kanji-magnifier) も存在する。「単機能ゆえのシンプルさ」だけでは差別化にならない。
3. **SEOで勝てる見込みが薄い**：「漢字拡大」「漢字 大きく」等の主要キーワードは、既に個人開発の無料ツールサイトやアプリストアページが上位を占めており、後発のSUGUDASUが新規ドメインで割り込む優位性がない。

## 5. JTBD比較（Before → Existing Solution → SUGUDASU）

**シーン**：封筒に「齋藤」と書く直前、「齋」の細部を確認したい

| 項目 | 既存Webツール（例：ベンリーツール） | SUGUDASU新設 |
|---|---|---|
| 時間 | 検索→クリック→入力→表示（既に確立済みUXで数十秒） | 同等（新規ドメインなので検索順位到達まで時間がかかる＝実質より遅い） |
| 認知負荷 | 既に「漢字拡大」で上位表示、迷わない | 同等以上にはならない |
| 入力負荷 | 同じ（1文字入力） | 同じ |
| 広告 | 不明（サイトによる） | SUGUDASU既存方針次第だが優位性は限定的 |
| 表示サイズ | 既に画面いっぱい対応済み | 同等 |
| 筆順確認 | ツールによっては非対応（アプリに劣る） | 新設しても後発 |
| スマホ操作性 | 既に縦書き/スマホ最適化済みのツールあり | ゼロから同等品質を作る必要 |

**結論**：SUGUDASUが既存手段より1ステップ以上優れる点を作り出せていない。優位性があるとすれば「SUGUDASU全体のブランド・カタログ内での発見性」だが、それは単体JTBDの正当化にはならない。

## 6. MVP（これ以上削ったら価値がなくなる最小仕様）

- 漢字入力→即時巨大表示（フォント：明朝体固定、字形の正確さ優先）
- サイズスライダーのみ
- 縦書き/横書きの自動切替（スマホ＝縦、PC＝横）

書き順アニメーションは「あれば競合に並ぶ」レベルであり、無くてもJTBDの核（字形確認）は成立する。ただし、書き順を削るとこの案は完全に既存の拡大表示専用ツール群と機能的に一致してしまい、差別化がゼロになる点に注意。

## 7. Reject条件（今回該当したもの含め最低3つ）

1. 「大きく表示するだけ」の無料Webツールが日本語圏に既に複数存在する → **該当（今回確認済み）**
2. 拡大＋筆順＋なぞりまで無料で提供するネイティブアプリが定着・高評価を得ている → **該当（今回確認済み）**
3. SEO主要キーワードが既存の個人開発サイト・アプリストアに支配されている → **該当（示唆あり、正確な検索ボリュームは未検証）**

---

## 8. Strategic Fit（5段階評価）

| 項目 | 評価 | コメント |
|---|---|---|
| JTBD適合 | 4 | ニーズ自体は実在する |
| ブランド適合 | 3 | 「3分で終わる」「単機能」は合致するが、独自性がない |
| 技術適合 | 4 | CJK統合漢字・異体字対応の設計は必要だが実装難度は低い |
| SEO適合 | 2 | 既存ツール・アプリが上位を占有 |
| 収益適合 | 2 | 差別化なきレッドオーシャンでの広告収益は薄い |
| スマホ戦略適合 | 3 | 例外化する価値はJTBD単体では正当化できるが、競合が既にスマホ最適化済み |
| 差別化 | **1** | ほぼゼロ。想定MVPが既存ツールの後追いになる |
| カタログ価値 | 2 | 「あって困らない」レベルで、積極的に作る根拠にならない |

---

## 9. 最終判定

**Verdict：Reject**

作るなら「大きく表示するだけの後発クローン」として作ることになり、既存の複数の無料ツール・高評価アプリに機能面で並ぶことすら難しい。

作らないなら、「同一JTBDを満たす無料代替手段が既に複数、しかも高い完成度で存在するため」が理由。

最大の不確実性は「SUGUDASUブランド内での発見性・回遊（カタログ効果）が、単体でのSEO劣勢を覆すほどの流入を生むかどうか」——ここだけは定量調査（実際のSUGUDASU全体のPV構成、内部回遊率）なしには判断できない。
