## CASE-2026-001

**事件名:** PureRef 期待値事件  

**争点:**  
ムードボード / 参照ボード型（PureRef 的）の高機能・整理・探索 UI を SUGUDASU に採るか。

**立法事実:**  
一時退避の需要はある。しかし PureRef は「並べて眺め · 整理 · 探索する」カテゴリ期待を形成する。実装すると SUGUDASU が知識・参照管理ツールに見える。

**適用条文:**  
WHY · Domain · Anti（複雑にしない · 提案しすぎない · 教え込まない）· F5

**判決:**  
**Reject** — PureRef 化 · 参照ボード化は採用しない。

**理由:**  
SUGUDASU は仕事の前工程のみ。参照を「管理・眺める」体験は滞在と管理行為を生む。普遍的な「一時退避」と「PureRef 一式」は別物である（後の Visual Grammar / カテゴリ期待と同型）。

**今後への影響:**  
一時退避は **Clip Stash（仮置き）** として、戻すだけに縮小して GO 可能。PureRef 機能セットの横展開は禁止。

**関連ADR:** なし（憲法判断）  

**関連Product:** `clip-stash`（対概念） · [`../products/clip-stash/philosophy.md`](../products/clip-stash/philosophy.md)

## CASE-2026-002

**事件名:** Clip Stash 管理機能事件  

**争点:**  
仮置きにタグ · フォルダ · 検索 · ノート · AI 分類等の「管理」機能を足すか。

**立法事実:**  
管理を始める機能は、プロダクトの存在理由（置いて戻す）を変える。「今は作らない」ではなく憲法上の Non-Goals。

**適用条文:**  
WHY · Domain · Persona · Anti · Commentary C-01 · C-10

**判決:**  
**Reject** — 管理のための機能。  
**GO** — 戻すためだけの仮置き（IndexedDB · 非送信 · 閉じた操作リスト）。

**理由:**  
判断軸: 「管理するため → Reject / 戻すため → 検討」。管理は前工程ではなく、仕事そのものの延長（整理）に踏み込む。

**今後への影響:**  
Clip Stash Non-Goals は再利用可能な判例テンプレ。Annotate の Visual Grammar と同型の「一式を採用しない」。  
「戻す」の出口（仮置き→外部 DnD）は [CASE-2026-010](#case-2026-010)。管理機能 Reject は維持。

**関連ADR:** なし（憲法判断） · 操作の HOW は製品 `specification.md` / `decisions`  

**関連Product:** `clip-stash`

## CASE-2026-003

**事件名:** Annotate（赤入れ）視覚言語 · Skitch 期待値事件  

**争点:**  
1. Skitch 型矢印 + テキスト注釈を持つか  
2. 矢印形状を変えるべきか  
3. コピーで競合否定（「Skitchではない」）を書くか  

**立法事実:**  
矢印単体は PowerPoint · Excel · PDF 注釈等と共有された普遍記号。矢印 + テキスト + 吹き出しは特定カテゴリ（Skitch 型）の視覚言語一式となり、「汎用注釈アプリ」期待を招く。

**適用条文:**  
WHY · Domain · Anti（教え込まない · 複雑にしない）· Commentary C-01 · **C-10 Visual Grammar**

**判決:**  

| 争点 | 判決 |
|------|------|
| 自由記述テキスト · 吹き出し | **Reject** |
| 矢印形状変更 | **HOLD**（今はやらない） |
| ポジショニング（WHY コピー） | **GO** |
| 「Skitchではない」ユーザー向け訴求 | **Reject**（競合基準に語らない） |

**理由:**  
守るべきは見た目より **期待値**。視覚記号は可、視覚言語一式は不可。JTBD は「共有できる状態へ整える」。競合名で語るとブランドが競合の影子になる。

**今後への影響:**  
Visual Grammar Rule を Commentary C-10 へ昇格。他ツールでも「カテゴリ一式の模倣」を Reject する際の参照判例。

**関連ADR:** なし（憲法判断） · 製品 HOW: [`../products/annotate/decisions.md`](../products/annotate/decisions.md)

**関連Product:** `annotate`

## CASE-2026-004

**事件名:** Hub アンケート（仕事コンテキスト）事件  

**争点:**  
1. Hub で利用目的を聞いてよいか（匿名なら F2 OK か）  
2. 「改善のため」なら提案しすぎないに抵触しないか  
3. 取得データをどう使ってよいか  

**立法事実:**  
複数解釈者が条文字面で「違憲」と判断。立法者は条件付き合憲の意図。条文だけでは Persona · 「提案」の範囲が再現できていなかった → 義解 · 本判例の必要性の証明。

**適用条文:**  
Persona（C-02）· Anti 提案しすぎない（C-07）· F2（回答本文）· Pain 起点（C-09）· 存在様式

**判決:**  
**条件付き合憲**（Phase H-UI-07）。次をすべて満たす場合のみ。

- 毎回 · 起動時に聞かない（10 ツール OR 14 日 · 回答後は基本非再表示）
- 自由入力 · 任意 · スキップ可 · Product 作業中は出さない
- 補足は「あなたの仕事を進めやすくするために使います。」
- 用途は検索辞書 · 検索例 · Hub IA のみ
- Persona 分類 · マーケセグメント · おすすめ生成 **禁止**
- 分析は Pain / Moment / Job へ正規化
- 回答本文の GA 送信禁止 · 初版サーバー送信なし

**理由:**  
争点の核心は F2 ではなく **Persona**。「匿名だから OK」「改善だから OK」は誤解釈。隣の同僚は自己改善のために聞き出さない。辞書改善でも邪魔する聴取は違憲。  
**PCT-6（任意性）:** 能力があっても常時介入する義務はない。既定は沈黙であり得る。

**今後への影響:**  
H-013 一文。義解 C-02 · C-07 · C-09 · **PCT-6** の補強。新機能の「ヒアリング」は本判例の条件を満たさない限り Reject。

**関連ADR:** なし（憲法判断） · Phase 仕様: [`../products/hub/PHASE_H-UI-07-work-context.md`](../products/hub/PHASE_H-UI-07-work-context.md)

**関連Product:** Hub (`hub`)

## CASE-2026-005

**事件名:** F2 非送信字面解釈事件  

**争点:**  
「非送信」は一切の HTTP / 外部取得を禁ずるか。

**立法事実:**  
AI 複数が「一切送るな」と解釈。立法意思は業務データの SUGUDASU 管理下への非送信 · 非保存。

**適用条文:**  
F2 · Commentary **C-05**

**判決:**  
**義解確定** — 通信そのものの全面禁止ではない。  
保護法益はユーザー成果物 · 入力 · 業務データの主権。  
OGP · 技術アセット取得等は、保存を伴わず Pain に不可欠なら直ちに違憲ではない。  
成果物アップロード · 解析目的保存は違憲。

**理由:**  
ブランドコピーと法的定義の分離。字面解釈は憲法運用として危険。

**今後への影響:**  
F2 判定は必ず C-05 を読む。F1〜F7 のチェックリスト字面だけで合憲宣言しない。

**関連ADR:** なし  

**関連Product:** 全コア · Sync は別線（[`../notes/SUGUDASU_SYNC_LINE.md`](../notes/SUGUDASU_SYNC_LINE.md)）

## CASE-2026-006

**事件名:** Present（ギフト）Reject · アーカイブ事件  

**争点:**  
AI ギフト提案（`present` · Amazon 導線）を現行ブランド憲法下で公開カタログに残すか。

**立法事実:**  
憲法制定以前の市場・アフィリエイト検証を兼ねた試行。ユーザー向けに「AIが提案」し、購入導線を前に出す。Hub に掲載され続けていた。

**適用条文:**  
WHY · Domain · Persona · Anti（提案しすぎない · AIらしさを出さない）· Product 判定ラベル `Reject` · PCT-6（できるから載せ続けない）

**判決:**  
**Reject** — Hub / ナビ / カタログから除外。URL はアーカイブ案内のみ（`noindex`）。新機能停止。同系統の新規採用停止。Legacy 保守ではなく **公開製品からの撤退**。

**理由:**  
**SUGUDASUのコンセプトに合わない。** 前工程（操作・段取り・整形）ではなく「何を贈るか」の提案が本体。提案しすぎない · AI を前面にする体験と衝突。検証目的は終わった。理由は更新履歴にも公開する（誠実さ）。

**今後への影響:**  
ギフト / アフィ誘導型の新規ツールは原則 Reject。景品・抽選の実務は `fair-draw` 側。

**関連ADR:** なし  

**関連Product:** `present` · [`../products/present/README.md`](../products/present/README.md)

## CASE-2026-007

**事件名:** 帳票チャネル名付き共有UI（Copy-First）事件  

**争点:**  
invoice / receipt で Slack・Teams・Chatwork 等の名前付きボタンにより「送る先」を SUGUDASU がサジェストしてよいか。

**立法事実:**  
Phase 1 は「送付文面コピー + ユーザー設定URL起動」でサーバー非送信（F2）を満たしていた。UI 上は5社グリッド＋送信先URL設定があり、連携機能に見える。憲法制定後の Copy-First（結果を持ち帰り元の仕事へ戻す）と衝突する。

**適用条文:**  
Domain（受け渡せる状態まで）· Persona（前に出ない同僚）· Anti §13–14（設定前提・囲い込みしない）· F5/F6（コピー/PDF）

**判決:**  
**Reject（UI）** — プラットフォーム名付き共有ボタン・送信先URL設定・帳票主面の𝕏シェアを撤去。  
**合憲に残すもの** — 送付文面コピー、共有用URLコピー、印刷/PDF。  
チャット共有 Phase 2 横展開は打ち切り。Webhook / OAuth 連携は引き続き Reject。

**理由:**  
技術的非送信と体験の意味は別。チャネル選択はユーザーの仕事場の話であり、隣の同僚は「Teamsで送っておいた」とは言わない。Pain は文面作成と PDF 手元化であり、チャットアプリ起動ではない。

**今後への影響:**  
共有UIは Copy-First（コピー動詞）を主CTAとする。チャネル名をブランドコピーやボタンに載せない。「詳細の奥に隠す」もサジェストの本質が残るため不可。

**関連ADR:** なし  

**関連Product:** `invoice` · `receipt`（`stamp` は既に PNG コピーのみで対象外）· `warikan`（残件の𝕏シェアは 2026-08-13 撤去）

**残件クローズ（2026-08-13）:**  
`warikan` の「𝕏 結果をシェア」、`sugudasu-growth.js` の `shareX*` / `openXIntent`、帳票 CTA 計測の死セレクタ、`.sg-btn-x` を撤去。`invoice` 見出しを Copy 動詞へ是正。監査メモ: `docs/notes/CASE_2026_007_RESIDUAL_CLEANUP_20260813.md`。

## CASE-2026-008

**事件名:** 裏紙「説明モード」（画面いっぱい・モード切替）事件  

**争点:**  
`uragami`（裏紙）に、ドラフト会議の「会議モード」に類する **名前付き「説明モード」**（表示を画面いっぱい · ヘッダー/ツール退避 · モード入場）を採るか。

**立法事実:**  
- モニタ差で「紙が小さい」痛みはある。Paper Fit（占有率）と Paper Zoom（見る距離）の二軸は既に設計済み。  
- ドラフト会議（`match-board`）の会議モードは **setup→meeting のワークフロー段階切替**（準備UIを隠しボードを広げる）であり、Fullscreen API や投影専用モードではない。  
- 裏紙の JTBD は最初から「説明のために描く」一段階。準備フェーズが無い。  
- 紙境界（机色 · 縁 · 接地影）を強めた直後であり、画面いっぱいで机を消す案は Paper Affordance と衝突する。

**適用条文:**  
- 製品 Mission（説明が速くなるか · `docs/products/uragami`）  
- ADR-000（裏紙で現実にできないことは実装しない）· ADR-007（一枚 · Fit/Zoom）  
- Persona（考えない · 教え込まない）· Anti（設定・モード増殖 · チュートリアル）· Domain（前工程のみ）

**判決:**  
**Reject** — 名前付き「説明モード」· ドラフト会議型の段階モード移植 · `requestFullscreen` による儀式的全画面。  
**合憲に残す／採るもの** — Paper Fit（占有率）の強化（既定を大きく · ジェスチャで可変）· 机の上に大きな一枚 · 境界を残したまま大きく見せる。  
**条件付き可（モード名なし）** — Esc 一発等で Fit を一時最大化する場合は、ラベル無し・一瞬・机/縁を消さないこと。

**理由:**  
1. モードは「今は通常か説明か」を考えさせ、開いたら紙だけ、に反する。  
2. ドラフト会議の会議モードは setup≠meeting があるから合憲寄り。裏紙に移植する前提が無い。  
3. Fit と「説明モード」は同じ痛みの二重解法で MECE でない。  
4. 全面化で机を消すと、色覚以前に「ここが紙」の認知（境界）が壊れる。  
5. Fullscreen API は権限・Esc・復帰の儀式が重く、3秒で描き始めるを壊しやすい。

**今後への影響:**  
裏紙および類似の「一枚キャンバス」系で、**画面占有の問題をモード切替で解く提案は原則 Reject**。占有率（Fit）と見る距離（Zoom）を分け、境界（Desk/Edge）を消さない。他ツールの「会議モード」を安易にコピーしない（JTBD 段階の有無を先に見る）。

**関連ADR:** [`ADR-007 Why One Sheet`](../products/uragami/ADR-007-why-one-sheet.md)（Fit/Zoom の HOW）· [`ADR-000`](../products/uragami/ADR-000-constitution.md)

**関連Product:** `uragami` · 対比 `match-board`（会議モードは別JTBD）

## CASE-2026-009

**事件名:** 漢字拡大・カタログ線引き（Hub Value / 端末）事件  

**争点:**  
1. 同一 JTBD が無料 Web で既に解けている単機能（紙に書く直前の漢字巨大表示）を、「SUGUDASU のブックマークに無いと困る」という Hub Value で採用してよいか。  
2. 利用がスマホで自然なことを、採用または排除の主軸（「スマホ例外」「スマホ主戦場禁止」）にしてよいか。

**立法事実:**  
- 案「漢字拡大」は、紙に書く直前に字形を巨大表示する極小 JTBD。学習・辞典・なぞりは意図的に持たない。F1〜F5 には乗る。  
- デューデリジェンスの結果、同一 UX（入力 → 巨大表示 → すぐ書く、登録不要・ブラウザ完結）の無料 Web が複数あり、拡大＋筆順のネイティブアプリも定着している。  
- 「SUGUDASUっぽい」（単機能・3分・非送信）は競合も満たしており、思想そのものが差別化になっていなかった。  
- 反論として、検索流入ではなく道具箱／Direct 再訪なら「ドメインにあること」自体に価値がある、という読みが出た。上限を置かないと便利ツール全集になる。  
- 初日の線引き案に「スマホ主戦場の仕事はコアに置かない」があったが、既存の割り勘（店頭会計の直後・ほぼスマホ）と衝突する。Brand Constitution に端末条項は無い。

**適用条文:**  
WHY · Domain（前工程のみ · 学習サイト化禁止）· 存在様式（再訪は次の実務であり習慣化・囲い込みではない）· Anti（複雑にしない · 提案しすぎない）· Product（ブラウザでできるだけでは採用しない · PC ブラウザで成立する仕事 · 適合高×市場低は横連携として採否）· 2026-08-13 逆引き辞典 Reject（コモディティ）

**判決:**  
**Reject** — 漢字拡大はコアカタログに採用しない（未実装。Hub/registry 追加なし）。  
**合憲に確定するもの**  
1. **Hub Value を採用の主因にしない。** Direct／ブックマークは再訪インフラとして Keep。ただし「困ったらまず SUGUDASU」という習慣化は存在様式と衝突し、採用理由にしない。  
2. **横連携（Adjacent）は同一仕事系列の直前・直後に限る。** 帳票・名簿・画像の隠す/切る・テキスト整形・会議の持ち帰り。生活ユーティリティ・学習・汎用変換は、Hub にあることだけでは GO にしない。  
3. **端末は採用・排除の主軸にしない。** Pain がスマホで起きても、ブラウザ完結かつ PC でも同じ仕事が終わるならコア可（割り勘）。ネイティブ必須、Hub／全ツールのモバイルファースト化、「スマホだから足す／足さない」は不可。

**理由:**  
「SUGUDASUっぽい」と「SUGUDASU が作るべき」は別である。競合が F1〜F5 を満たす領域では、憲法適合は競争優位ではない。Hub Value を主因にすると「あったら便利」が全案件の GO になり、昨日の逆引き Reject と同型のコモディティを再搬入する。漢字拡大は請求・差分・班分けの隣に自然に来ない。  
端末を軸にすると、割り勘・QR・当日欠席が「例外」になり、例外表が憲法になる。PC 原則が守るのはネイティブ必須と Hub のスマホアプリ化であり、Operate の発生場所ではない。

**今後への影響:**  
新規ツール DD は、憲法を競合が既に満たしている場合それを差別化として評価しない。競合がまだ解いていない具体的 JTBD、または競合では解きにくい制約を1つ以上特定できなければ Reject。横連携は仕事系列で見、Amazon 棚を新原理にしない。憲法本文は改正しない（運用の明文化）。

**関連ADR:** なし（憲法判断）  

**関連Product:** 不採用（漢字拡大）· 対概念 `warikan`（スマホ主戦場でも合憲）· 2026-08-13 `reverse` Reject（同型コモディティ）  

**原料:** [`logs/2026-08-14_kanji-magnifier_source.md`](./logs/2026-08-14_kanji-magnifier_source.md) · レビュー [`logs/2026-08-14_catalog_line.md`](./logs/2026-08-14_catalog_line.md)

## CASE-2026-010

**事件名:** Clip Stash × Edge Drop（卓上・出口）事件  

**争点:**  
1. Microsoft Edge「ドロップ」の機能セット（画面端パネル · 種類フィルタ · ピン留め · 画像グループ · 細かいカスタマイズ · 端末間同期）を仮置きへ移植してよいか。  
2. 「戻す」はクリップボードコピーに限るか。仮置きから他アプリへ DnD する出口は管理か。  
3. 複数カードのグループ化は、一括操作と同一か。

**立法事実:**  
- Edge Drop は「自分のデバイス間でファイルやメッセージを共有する場所」。DnD で途中に置く体験を持つが、Microsoft は終了を案内しており、競合の現行仕様を追う対象ではない。  
- 現行の仮置きは **外部 → 仮置き**（置く）とダブルクリックコピー（戻す）が強い。作業の実態は PowerPoint / Word / エクスプローラーへ **今すぐ渡す** ことであり、保管ではない。  
- 種類フィルタ · ピン留め · 手動グループは「探さない。置いてある。」を壊し、仮置きを情報管理空間にする。  
- 画面端ホットエッジは、仮置きが主作業面である前提と衝突する。  
- 端末間同期と「自分への送信」は Sync レーンであり、コア仮置きの通信ではない。

**適用条文:**  
WHY · Domain（前工程のみ）· Anti（複雑にしない · 提案しすぎない）· Commentary C-01 · **C-10 カテゴリ期待** · CASE-2026-001（カテゴリ一式の模倣）· CASE-2026-002（管理 Reject / 戻す GO）· CASE-2026-007（Copy-First。チャネルへ送らない）

**判決:**  

| 争点 | 判決 |
|------|------|
| Edge Drop 機能セットの移植 | **Reject** |
| 画面端パネル · フィルタ · ピン留め · 手動グループ · カスタマイズ · 同期 · 自分への送信 | **Reject** |
| 仮置き → 外部への DnD（出口） | **GO**（「戻す」の拡張。保管ではない） |
| 画像 / PDF の大型プレビュー（確認のみ） | **GO** |
| ドラッグ中のドロップ先明示 · 入口 Strip を消さない | **GO** |
| 複数選択 → 一括削除 / 一括出口 DnD | **条件付き GO**（グループ化・名前付け・結合は Reject） |

**理由:**  
SUGUDASU 仮置きは Edge Drop の簡易版ではない。**作業中の素材を、次の場所へ渡す卓上**である。保存は「あとで取り出す」。仮置きは「今、次へ渡す」。出口 DnD は整理ではなく持ち帰り（Copy-First）の別経路である。フィルタやピン留めを足した瞬間、ユーザーは仮置きを管理空間として扱い始め、CASE-2026-002 に戻る。グループは「この3枚をグループAとして保存」という保管メンタルを生む。複数選択は作業操作の効率化に限り、整理 UI にしない。

**今後への影響:**  
クリップボード管理アプリ · 端末間ドロップ · ホットエッジランチャーの機能カタログを仮置きに足す提案は、便利さでは覆さない。出口・確認・一括操作の HOW は製品仕様へ。憲法本文は改正しない。

**関連ADR:** 製品 HOW [`../products/clip-stash/specification.md`](../products/clip-stash/specification.md) ADR-CS-004〜006 · 実装 [`../products/clip-stash/SPEC_HANDOFF.md`](../products/clip-stash/SPEC_HANDOFF.md)

**関連Product:** `clip-stash`

**原料:** [`logs/2026-08-15_clip-stash_edge_drop.md`](./logs/2026-08-15_clip-stash_edge_drop.md)

## CASE-2026-011

**事件名:** PowerToys 摩擦・新規HTML 事件  

**争点:**  
1. Microsoft PowerToys の機能セット（常駐・ランチャー・ウィンドウ管理・OCR・AIペースト・設定）を SUGUDASU へ移植してよいか。  
2. 抽出された JTBD のために新規 HTML を足してよいか。  
3. 仮置きへ Adapt 常時ボタン・矩形クロップ・セッション自動破棄を今すぐ足してよいか。

**立法事実:**  
- PowerToys は OS↔アプリの摩擦をネイティブ特権（常駐・キーフック・オーバーレイ）で解く。SUGUDASU は業務データ↔ブラウザ。特権の模倣はサンドボックスと憲法（登録不要・静的配信・設定させない）で破綻する。  
- 有効な摩擦は 3 つに限られる: 形式の非互換、視認と確認の中断、単純反復の摩耗。  
- Peek（確認）と Handoff（出口）は CASE-2026-010 で既に合憲・出荷済。  
- 汎用 OCR は 90% 精度が 100% 目視校正を強制する。日本語帳票・縦書き・表構造と WASM モデルサイズ（15MB 超）は Calm UX と静的俊敏性を壊す。  
- 監査の「即時実装」（カードフッターの形式コピー常時表示、テキスト全画面 Peek、タブ閉じ破棄）は CASE-2026-010 の「コピーが最短導線」「編集しない」「text/table は現行サイズ」および IndexedDB 永続と衝突する。

**適用条文:**  
WHY · Domain · Anti（複雑にしない · 教え込まない · 設定させない）· F5 · Commentary C-01 · C-10 カテゴリ期待 · CASE-2026-001 / 003 / 010（カテゴリ一式の模倣）· CASE-2026-002（管理・履歴 Reject）· CASE-2026-007（Copy-First）· CASE-2026-009（新規 HTML を Hub Value で足さない）

**判決:**  

| 争点 | 判決 |
|------|------|
| PowerToys 機能セットの移植 | **Reject** |
| Always On Top · Awake · FancyZones · Run · Workspaces · Keyboard Manager · ZoomIt 等 OS常駐/設定/学習 | **Reject** |
| 汎用 OCR / Text Extractor / AI ペースト | **Reject**（仮置きには到来しても入れない。別プロダクトはモデル条件が揃ってから再審） |
| クリップボード履歴の新規 HTML | **Reject** |
| 新規ツール（新規 HTML） | **本件監査では 0**（カタログ全体の凍結ではない。有効 JTBD は既存の入口/出口へ翻訳） |
| Peek（画像/PDF 確認）· 出口 DnD | **Keep**（CASE-2026-010。再審しない） |
| 仮置きの形式コピー常時ボタン | **Reject**（表の出口は `table-conv`） |
| テキスト全画面 Peek · 矩形クロップ | **着手不可**（再開条件はレビューログ。HOLD を着手可と読まない） |
| タブ閉じ破棄 | **Reject** |
| 画像一括リサイズ · Normalize 自動判別 · 画像内スポイト · PowerRename | **PARK（範囲付き）**。仮置きには入れない。Normalize に一括改名を足さない。トリガー前は実装しない |

**理由:**  
PowerToys はユーティリティ OS 拡張のカテゴリ期待を形成する。一式を足すと SUGUDASU が常駐ランチャーに見える（C-10）。OS 責務は Domain 外。OCR と生成 AI ペーストは非決定論であり、置いたバイトを変質させない原則と実務事故リスクに反する。新規 HTML 0 は **本件監査の結論** であり、今後の全カタログ凍結ではない（CASE-2026-009 と同型の「あったら便利では足さない」）。形式変換の JTBD 自体は価値があるが、仮置きフッターのボタン増殖はヒックの法則に反する。主座は既出荷の `table-conv`。Normalize は1テキストの貼り先整えであり、多数対象の一括改名とは JTBD が違う。Crop は「切り出して渡す」なら出口、「新カード複製」なら編集に近い。境界はプロトタイプでユーザーに聞くまで製品に入れない。

**今後への影響:**  
ネイティブ特権ユーティリティ（PowerToys · ランチャー · ウィンドウマネージャ · 画面 OCR）のカタログをコアに足す提案は、便利さでは覆さない。PARK はスコープと再開トリガー無しでは書かない。HOLD を着手可と読まない。外向けに「機能を増やさない」と宣言しない。憲法本文は改正しない。

**関連ADR:** なし（憲法判断）。仮置き HOW は CASE-2026-010 の製品仕様を維持。  

**関連Product:** `clip-stash`（Peek/Handoff は既存）· `table-conv`（表の形式出口）· `normalize`（1テキストの整え。一括改名は載せない）· 画像系（一括リサイズは PARK）· 不採用（PowerToys 移植 · OCR ツール）

**原料:** [`logs/2026-08-15_powertoys_friction_source.md`](./logs/2026-08-15_powertoys_friction_source.md) · レビュー [`logs/2026-08-15_powertoys_friction.md`](./logs/2026-08-15_powertoys_friction.md)

## CASE-2026-012

**事件名:** TXT-Crypter 型テキスト暗号URL 事件

**争点:**  
1. サーバー非保存・登録不要・暗号データをURLに閉じ込めるステートレス構造は、F2/F3 と一致するからコア新規ツールとして GO か。  
2. Secret Copy Link · 仮置きの暗号ロック · Wiki/Notion 埋め込みを SUGUDASU コアに載せてよいか。  
3. Vault UI を削れば「単機能テキスト伏字」として合憲か。

**立法事実:**  
- [TXT-Crypter](https://tc.chigusa-web.com/) はブラウザ完結のテキスト暗号化と復号URL埋め込みを無料提供。FAQ 主座は Notion 等への平文回避。復号 OSS 公開済み。  
- 提案は「思想が完全一致」としつつ、応用ユースケースはチャット秘密共有・仮置き画面共有ロック・手順書埋め込み。  
- SUGUDASU ユーザの標準動線は整える→コピー/DLで手元へ戻す。秘密の長期保管・パスフレーズ運用は製品が代替していない。  
- 仮置きは CASE-2026-010/011 により変質させない卓上。加工・Adapt・暗号退避は境界外。  
- 同型競合が既に無料で存在する（CASE-2026-009 と同型の市場事実）。

**適用条文:**  
Persona · Domain · Anti（教え込まない · 複雑にしない · 管理させない）· Commentary C-10 カテゴリ期待 · Product Constitution（判定順 · Hub Value 非採用）· CASE-2026-002 / 007 / 009 / 010 / 011 · F5 · F7

**判決:**

| 争点 | 判決 |
|------|------|
| コア新規 HTML（テキスト暗号URL / 伏字リンク） | **Reject** |
| パスワードマネージャ / Vault UI | **Reject** |
| 仮置きへの暗号退避・画面共有ロック | **Reject** |
| Wiki/Notion 埋め込みを主座にした製品 | **Reject** |
| チャット用 Secret Copy Link のコア掲載 | **Reject**（コア）。Secret / 別置きは立法事実が揃うまで再開しない |
| クライアント暗号 + URL ペイロードという技法 | 製品 GO の根拠にしない。Sync / Secret 既存線で必要なときのみ |

**理由:**  
F1〜F4 の技法相似と製品 Domain の一致は別物。判定を仕組みから始めると CASE-009（SUGUDASUっぽいだけでは足りない）を繰り返す。TXT-Crypter の本丸はメモ上の秘密保管であり、Copy-First の3分実務とは隣だが同一でない。パスフレーズ運用は教え込みと F7（安全の過剰断定）に触れる。Vault UI を削っても Wiki 埋め込み JTBD は保管隣接のまま。仮置き暗号は卓上の変質・加工導線であり CASE-010/011 と衝突する。チャット平文の Pain は認めるが、会社公認の配送・既存 Vault Send・マスクして持ち帰りが先で、コアカタログに暗号ユーティリティを足す立法事実はない。

**今後への影響:**  
「非送信・ステートレス・URLにデータを閉じ込める」を理由にコア新規 HTML を提案してはならない。技法の再利用と製品 GO を混同しない。憲法本文は改正しない。

**関連ADR:** なし（憲法判断）

**関連Product:** 不採用（コア暗号URLツール）· `clip-stash`（暗号退避しない）· マスク/赤入れ（画像の隠す。テキスト暗号保管ではない）· `secret/file-transfer`（別判定の Secret · 本件でコア化しない）

**原料:** [`logs/2026-08-15_txt_crypter_url_crypto.md`](./logs/2026-08-15_txt_crypter_url_crypto.md)
