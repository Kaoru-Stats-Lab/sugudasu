# SUGUDASU Graph — 色つけ必須裁定

**Date:** 2026-08-14（HEX/ピッカー許容を明記）  
**Verdict:** **色ロール変更は必須。** 入力は **HEX（VI/CI）＋ピッカー（それ以外）** でよい。  
**禁止なのは狭い:** 全要素を個別に塗るエディタ、およびフォント／余白まで含むテーマエディタ。

**Supersedes in part:** [`GRAPH_R1_PROJECTION_COLOR_JUDGMENT.md`](./GRAPH_R1_PROJECTION_COLOR_JUDGMENT.md) の「色を一切選ばせない」「色ピッカー禁止」

## 一行裁定

> **グラフの色つけ（特定ロール）は必須。**  
> VI/CI がある会社は **HEX を持っている** → HEX 入力で載せる。  
> それ以外は **ピッカーレベル**で主色・強調を変えられれば足りる。  
> 「フル色エディタ／全要素ピッカー／テーマエディタを全面禁止」は **きつすぎる**。  
> 禁止は **グラフを Illustrator 化するUI** だけに絞る。

貼付後 SVG は編集できないため、色は **出力前**に決める。

## 本命ユースケース — 特定項目の色だけ変える

参考スクショ: [`fixtures/acceptance/ref/ref-accent-column-visitors.png`](./fixtures/acceptance/ref/ref-accent-column-visitors.png) · [`fixtures/acceptance/ref/ref-accent-bar-telework.png`](./fixtures/acceptance/ref/ref-accent-bar-telework.png)


| 例 | やっていること |
|----|----------------|
| 来場者数（縦棒） | 6〜11月は同色、**12月だけ濃いアクセント** |
| テレワークの良かった点（横棒） | 下位は薄い青、**1位だけ濃い紺** |

これは「テーマを一式変える」でも「全棒を虹色」でもなく、

> **系列の基本色 + 特定カテゴリ1（〜少数）を強調色に差し替える**

に尽きる。色ロール必須の **中核シナリオ** とする。

### 契約（Settings）

```text
series_color     … 通常の棒／線
accent_color     … HEX またはピッカー
accent_categories… ["12月"] または ["通勤のストレスがなくなった"] など
```

Renderer は `matched_rule_id` を見ず、Spec/Settings のカテゴリ指定に従ってその mark だけ `accent` を塗る。

### 一緒に欲しくなるが、色とは別ゲート

提示例には次もある。色 MUST と同時実装必須にはしない（別 Acceptance）:

| 要素 | 扱い |
|------|------|
| 棒上／棒横の **値ラベル**（1,000 · 72% 等） | Presentation Settings 候補 · 可読性に効く |
| 図内タイトル | POC 上は原則デッキ側。R1 必須にしない |
| 単位（人）（%）の軸付近表示 | 単位ロール · 既存 Gap |

まずは **特定項目の色差し替え** を Color Must の Done 条件にする。

**ラボ実装（2026-08-14）:** [`lab/graph-color-lab.html`](./lab/graph-color-lab.html) · helpers `assets/graph-presentation-settings.js` · `npm run test:graph-presentation`  
ローカルはリポジトリを静的サーバで開き、ラボ HTML を表示（`fetch` で Rules を読む）。

## やる / やらない（境界）

### MUST · GO

| 対象 | UI |
|------|-----|
| `series` 主系列色 | プリセット ＋ **HEX** ＋ **ピッカー** |
| `accent` 強調色 | 色は HEX/ピッカー。**対象カテゴリを1〜少数選ぶ**（例: 12月だけ / アンケート1位だけ） |
| 達成/未達・第2系列 | **データがあるときのみ** · 同上 |

これは Presentation Settings であり Graph Editor ではない。  
ロールが 2〜4 個なら、ピッカーがあっても「3分」と両立する。

### 許容（きつく締めない）

| 案 | 判定 |
|----|------|
| ロール用カラーピッカー | **GO** |
| ロール用 HEX テキスト | **GO**（VI/CI 向け） |
| よく使う色の短いプリセット列 | **GO** |
| コントラスト警告（薄い色を選んだとき） | **GO**（投影耐性と整合） |

### MUST NOT · REJECT（ここだけきつく）

| 案 | 理由 |
|----|------|
| **全要素ピッカー**（軸・グリッド・目盛・各棒を個別に無限指定） | 資料デザインツール化 · 3分崩壊 |
| **テーマエディタ**（色＋フォント＋余白＋線幅を一式デザイン） | Graph Editor / 簡易 Illustrator |
| 目標列が無いのに達成色を塗る | 嘘描画 |
| 虹色で全カテゴリ必須色分け | 装飾・投影崩れ |
| デッキ貼付後の色直しを一次解 | 編集不可ロック |

```text
GO:   色ロール × (HEX | ピッカー | 短いプリセット)
NG:   全要素を塗るUI · テーマ一式エディタ
```

## 「禁止がきつくないか」への答え

前版の「フル色エディタ／全要素ピッカー／テーマエディタ禁止」は、  
**ロール用ピッカーまで禁じると読まれうる**ので、本版で修正する。

| 言い方 | 正しい読み |
|--------|------------|
| フル色エディタ禁止 | チャート全体のデザインスタジオは作らない |
| 全要素ピッカー禁止 | 軸やグリッドまで1つずつ塗らせない |
| テーマエディタ禁止 | フォント・余白まで含むブランドキットUIは作らない |
| ピッカー禁止？ | **しない。ロール用ピッカーは必須寄り** |
| HEX 禁止？ | **しない。VI/CI は HEX が本命** |

| 文書 | 関係 |

## 実装順序（推奨）

1. S0 投影耐性デフォルト  
2. 色ロール API（`series` / `accent`）  
3. UI: プリセット ＋ **HEX** ＋ **ピッカー** ＋ 強調項目  
4. データ連動の達成色・第2系列色（R1.x）

## Acceptance

- **特定項目アクセント:** 通常色の系列のうち1カテゴリだけ強調色 → 来場者12月／アンケート1位型が再現できる  
- VI 想定: HEX で主色変更 → 再出力  
- 非 VI: ピッカーで強調色 → 特定棒が一目で分かる
