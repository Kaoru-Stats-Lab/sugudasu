# SUGUDASU Graph — 投影・遠距離の色／コントラスト裁定

**Date:** 2026-08-10  
**Role:** Senior UI/UX（＋現行 Renderer デフォルトとの突合）  
**Scope:** VICI が固い大企業向けブランド色ではなく、**SUGUDASU デフォルト色**  
**Related:** [`GRAPH_R1_ROUNDTRIP_JUDGMENT.md`](./GRAPH_R1_ROUNDTRIP_JUDGMENT.md) · [`PRESENTATION_OUTPUT_CONSTITUTION.md`](./PRESENTATION_OUTPUT_CONSTITUTION.md) · **配色トークン正本** [`GRAPH_DEFAULT_PALETTE.md`](./GRAPH_DEFAULT_PALETTE.md)

## 問題

プロジェクタ投影では:

1. **色が淡く見える**（洗われる・彩度が落ちる）
2. **離れると視認性が落ちる**（文字・細い線・淡色が先に消える）

VICI（ビジュアル・アイデンティティ）が厳密な組織は自社色で差し替える世界。  
SUGUDASU の主戦場は「毎回デザイナーに頼めない担当」なので、**デフォルトが投影に耐えること**が一次品質。

---

## 一行裁定

> **デフォルトは投影耐性を強くする。意味は色だけに載せない。**  
> 「投影ハイコントラスト」は opt-in 1 プリセットまで。  
> **ロール色の HEX / ピッカーは許可（必須寄り）。**

## 解決の優先順位（UI/UX）

### 1. 本命 — デフォルトを「会議室の後ろの席」基準にする

画面上で「きれいなパステル」より、**投影＋距離でまだ読める**を勝たせる（POC-009: 可読性 ≫ 装飾）。

| 要素 | 方針 | 現行 R1（参考） | 方向 |
|------|------|-----------------|------|
| シリーズ塗り | 中〜高彩度、明度を下げすぎない・上げすぎない。淡いパステル禁止 | `#2F6FED` | 維持〜やや濃く／コントラスト検証 |
| 文字 | 近黒。グレーすぎ禁止 | `#374151` | **濃く**（例: スレート900寄り）を検討 |
| 軸・ベースライン | 文字と同程度に濃く | axis `#6B7280` · baseline `#111827` | axis を濃く |
| グリッド | あってもよいが **主役を食わない薄い線**。消えなくてもよい | `#E6E8EC` | 投影ではさらに薄くてよい／オフ opt |
| 線グラフ | 細線は距離で消える | `line_width: 2` | **投影では 2.5〜3.5** 相当をデフォルト寄せ |
| 棒 | 単色ベタは長さが主エンコーディングなので色依存は低い | 単色 | 塗りは濃く。枠線 1px 近黒で輪郭を残すと投影に強い |

**原則:** 色相の美しさより **輝度コントラスト（明るい背景×暗いインク）**。

### 2. 本命 — 色に意味を一人で担わせない

投影で色が溶けても壊れない設計:

| エンコーディング | 役割 |
|------------------|------|
| 位置・長さ | 主（Bar/Column/Line の本体） |
| 文字ラベル | 必須（カテゴリ・目盛・単位） |
| 線幅・マーカー | 距離耐性 |
| 色 | **補助**。達成/未達は色＋形（目標線・並び）で二重化（Gap B-data 時） |

「同じ色のベタ塗りが弱い」への答えは、まず **値ラベル／目標線／系列差** であり、虹色パレットUIではない。

### 3. 許容 — opt-in「投影ハイコントラスト」1つ

`deck_*` スロットと同様、Presentation Settings の **用途プリセット**:

| id | 内容 |
|----|------|
| `proj_contrast`（仮） | 文字・軸をより濃く、シリーズをより飽和、線を太く、グリッド弱め |

- デフォルトにしない必要はない、という議論もあるが:  
  **画面共有・印刷・PDF** では強すぎて「うるさい」ことがある → まずは **通常デフォルトを投影寄りに寄せ**、さらに足りない人だけ opt-in
- 証拠: 投影の色あせは **広く知られた現象**（個人体験に閉じない）。`proj_safe`（下余白）より一般化してよい
- **ロール用色ピッカー / HEX は許可**（Color Must）。テーマ一式エディタと全要素ピッカーだけ禁止

### 4. やらない

| 案 | 判定 |
|----|------|
| ユーザーがブランド色を逐一・全要素指定 | REJECT（Editor） |
| **主色 / 強調色など色ロールを少数変える** | **MUST**（Color Must 裁定） |
| VICI 準拠の企業テーマを製品に内蔵 | REJECT / Outside（企業向け別線） |
| パステル多色で「きれいなダッシュボード」風 | REJECT（投影で死ぬ） |
| 赤緑だけに達成を載せる | REJECT（色覚・投影の二重リスク） |
| 「PPTで色を直せ」を一次解 | REJECT（編集不可経路あり） |

VICI が厳しい会社: **主色ロールでブランド色を載せて再出力**が一次。SVG を渡して彼らの側で差し替えるのは二次。

## デフォルト vs スロットの関係

```text
S0  投影耐性のある色・字・線（全員の底上げ）     ← 今すぐ疑うべき
S1  配置スロット（半面 / 全面）
S2  プレビュー（半面フレームで「淡くないか」も見る）
opt  proj_contrast / proj_safe（後者は証拠弱め）
```

Acceptance では「ノートPC画面できれい」だけでなく、可能なら **明るめ投影／縮小表示**で文字と棒が残るか見る。

---

## 現行デフォルトへの具体チェック（実装時メモ · 今は裁定のみ）

実装キューに入れるときの最小変更候補（Editorなし）:

1. `text_color` / `axis_color` を濃くする  
2. `line_width` を上げる  
3. 棒に暗い stroke を 1px 足す（塗りは維持可）  
4. （任意）`proj_contrast` プリセットでさらに一段  

数値の確定は Acceptance（半面縮小・投影想定）のあとでよい。
