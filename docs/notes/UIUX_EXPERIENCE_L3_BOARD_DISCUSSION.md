### 0.4 文献・標準・DSが言うこと（2026-07-30 追記）

提督指摘: **印刷は既に sticky ヘッダーにあり、体験として印刷を特別視しているのは否めない。**

| 出典 | 結論（E-L3への含意） |
|------|----------------------|
| **IEC 60204-1 / 機械操作色** | 緑は Start/On・「通常状態の開始」に**許可**。赤は非常停止。**「印刷専用色」規定はない**。複合機の緑大ボタンは IEC 60417-5104「Start of action」＋慣行色 |
| **AMCIS（ボタン色分化）** | コントロールの**色分けは探索速度・態度を改善**。手がかりを重ねすぎると逓減 |
| **Nielsen / Carbon「1 primary」** | **画面（ページ）に視覚的主CTAは原則1つ**。二つ並べると主が消える |
| **NN/G 視覚階層** | 重要度は色・位置・大きさで伝える。**配置も階層信号** |
| **SAP Fiori Action Placement** | ヘッダー＝エンティティ向け**グローバル／常時可視**アクション。**ページ全体で primary は1つ**（header+footer横断）。ワークフロー完了は本来 footer 寄りだが、例外で header にも置ける |
| **Sticky CTA 実務研究** | ビューポート固定のCTAは**完了行動を特権化**し転換を上げる（配置＝優先度） |
| **Carbon Export pattern** | Print / Download / Export は**ラベルとアイコン**で区別。**印刷だけ別セマンティック色**とはしない（役割は primary/secondary） |

**合成（文献側の仮結論）**

1. 「緑＝印刷専用」を支持する学術結論はほぼない。産業色はむしろ **Start／通常開始／外へ出す開始**。
2. 一方「印刷を特別視している」は**色の話ではなく配置の話**として文献と一致する。sticky ヘッダー印刷は、そのツールにおける **page-primary exit の特権スロット**を既に占有している。
3. したがって E-L3 の本丸は「緑を広げるか」より **誰が唯一の primary exit を持つか**:
   - Print-Finish（ヘッダー印刷あり）→ 特権スロットは印刷。本文の ZIP/下書きDL は同色同重量にしてはならない（1 primary）。
   - Bake-Download（印刷ヘッダーなし／弱い）→ 特権スロットは ZIP/提出DL でよい。ここを青のままにすると「完了色」が系統分裂する。
4. 企業DSは「印刷とDLで色を分ける」より **同一トークン＋配置・ラベルで役割分担** を採りやすい。

→ 仮総意の更新候補: **L3緑＝その画面の「特権的持ち帰り出口」色**（多くの帳票ではヘッダー印刷が占有）。Bake 画面では同じトークンを ZIP に渡す。印刷専用に閉じる案 P も、「色でさらに印刷を聖域化する」読みとしては配置特権と二重になる。

### 0.5 Copy-First と印刷（提督所見 · 2026-07-30）

| 所見 | 含意 |
|------|------|
| Output によっては **DLしたあと結局印刷**する | 印刷は「唯一の完了」ではなく、紙経路への**ショートカット**になり得る |
| プロダクト全体は **Copy-First**（CASE-2026-007 · 持ち帰り） | 主完了の学習は **コピー（L2）** が先。印刷を chrome で特権化すると Copy-First と視覚的に競合する |
| 印刷は悩ましい | 帳票では紙が本番、変換系ではコピーが本番、Bake ではファイルが本番 — **完了系統ごとに印刷の重みが違う** |
| **ヘッダーに置かないことは確定** | sticky ヘッダー印刷ボタンを廃止する（配置特権を外す）。設置場所は本文・プレビュー近傍など **文脈内**へ |

**体験モデル（更新）**

```text
Copy-First（主）: 結果を手に持ち、元の仕事へ戻る          → L2 青（操作点確認は C+）
紙が要るとき:     印刷 = ブラウザ印刷ダイアログへの shortcut → L3 緑だが chrome ではない
ファイルが要るとき: DL/ZIP = 最終ファイル出口                 → 同じ「出口」トークン候補（E-L3 色は未決）
```

ヘッダー印刷を外すと、文献上の「sticky＝特権 primary」問題は解消方向。残るのは **色トークンを印刷とDLで共有するか**（E-L3 本体）。

## 1. 各立場の討議

### 1.1 CTO

**読み取り**
- 契約と DESIGN の不一致は Tech Adoption と同型の負債。Agent が毎回「どっち？」と聞くか、勝手に寄せる。
- `bake_download` の S1 を契約で L3 と書きながら UI が青なのは、**機械ゲート不能**（何が正か不明）。
- 案 P なら契約 §2/§3.2 を印刷専用に書き戻し、Bake は L2 のまま固定。案 E/G なら DESIGN §3.2 を「出口」に書き換え、Bake 主CTAを緑へウェーブ。

**見解**
- 意味は **1語で言える**こと: 「緑＝外へ出す出口」か「緑＝紙だけ」か。中途半端な「だいたいファイル」は例外表地獄。
- 下書き JSON / Continue Later の「ダウンロード」を緑にすると、印刷緑と **出口が複数**になり 1画面1つルールが壊れる → どの案でも **最終成果物以外のファイル保存は L3 禁止**を例外表に書く。

**推奨:** 文書衝突解消が第一。製品的には **案 E または G**（Bake を青のまま放置しない）。案 P を採るなら契約の bake→L3 行を削除するコミットが必須。

---

### 1.2 CMO

**読み取り**
- 帳票LPの約束は「PDF保存・印刷」。緑＝印刷は流入後の学習として強い（ヘッダー緑は既にブランド化）。
- 一方 watermark / pdf-images は「ZIPで手元へ」が完了であり、Copy-First の持ち帰りと同型。ここだけ青だと「完了色」が系統で分裂し、Hub 横断の信頼感が薄い。

**見解**
- マーケコピーで「印刷専用の緑」と宣伝しているわけではない。ユーザーが学ぶのは **「緑を押すと仕事が手元に出る」**。
- 案 P（印刷だけ緑）は帳票クラスタには美しいが、Bake クラスタでは完了が青のまま → 「SUGUDASUの完了は青？緑？」が残る。
- 下書き保存を緑にすると「送ってよい完成物」と誤解されサポート事故 → **最終成果物のみ緑**。

**推奨:** **案 E（成果物出口）**。印刷を特別視しすぎない。ただし 1画面1つの緑は死守（印刷と ZIP を同じ画面に二つ置かない設計）。

---

### 1.3 CPO

**読み取り**
- 完了系統を潰さない、は既決。Print と Bake は別系統だが、**出口の色を共有してよいか**が本問。
- Copy-First（チャネル非接続）と矛盾しない: コピーは L2、紙/ファイル出口は L3、という分担が憲法の持ち帰りと整合。
- P0 で内部緑を剥がした成果を守る。広げすぎ（「ポジティブなら緑」）は Gemini が拒否した世の中の総意側であり、**採らない**。

**見解**
- 案 P: 複合機メタファーは美しいが、Bake を「青の主CTA」に固定すると、契約の completion→色表が嘘になる。
- 案 E: 契約・P0・SYNTHESIS 尖りと一致。実装は ZIP/提出DL を緑へ寄せるウェーブが必要（今は青が多い）。
- 案 G: 「紙+ローカル最終ファイル」は運用しやすい。下書きJSONを明示除外できる。E と実質近いが、境界語が明確。

**推奨:** **案 G を契約語にし、運用は案 E と同一集合**（印刷·提出PDF/画像·ZIP·CSV最終DL）。内部名 Bake は UI に出さない（既決）。  
尖り: 案 P は「ヘッダー印刷の聖域」を守りたい派向けだが、完了系統の色一貫では劣る。

---

### 1.4 シニアUIUXデザイナー

**読み取り**
- 3層の学習: L2＝進める / L3＝外へ出す / 成功＝別チャネル（C+）。L3 を印刷だけに閉じると、Bake の主完了が L2 に落ち、**「進む」と「持ち帰る」が同色**になる（視覚的に完了が弱い）。
- 1画面1つ緑は空間ルール。invoice でヘッダー印刷緑があるとき、下の「下書きダウンロード」を緑にしない（既に白/青系）。
- watermark は印刷ヘッダーが無い/弱い画面が多く、ZIP が唯一の出口 → ここを緑にすると階層が立つ。

**見解**
- 緑のラベルは動詞で揃える: 「印刷 / PDF」「ZIPで保存」「CSVをダウンロード」。色だけで意味を背負わせない。
- セカンダリの白枠DL（補助・中間）と L3 緑（主出口）を混在させないチェックリストが要る。

**推奨:** **案 E/G**。DESIGN §3.2 の見出しを「印刷・PDF」から「成果物出口（印刷 / 最終ファイル）」へ改訂。`.sg-btn-print` は印刷専用クラス名のまま残し、Bake 用は `.sg-btn-export` 別名でも同トークン（`--sg-print-cta`）を共有してよい。

### 1.5 認知科学者

**読み取り**
- 色カテゴリは少ないほど安定する。今ユーザーが学習している緑は「ヘッダーの印刷」。Bake を突然全部緑にすると再学習コストがあるが、**青のまま「完了」も系統間で干渉**する（帳票は緑完了、画像は青完了）。
- 物理メタファー: 複合機の緑＝紙排出。自販機の着地＝ファイル。どちらも「装置の外へ出た」。画面内の +5分は装置内調整 → 緑禁止は認知的に正しい（P0 支持）。
- コピーは不可視の持ち帰り（C+で別チャネル）。可視の持ち帰り（紙・ファイル）を緑にまとめると、「手元化」スキーマが一本化される。

**見解**
- 案 P はメタファー純度は最高だが、Bake ユーザーは「完了色」を別途学習させられる。
- 案 E/G は「外へ出た」で圧縮でき、Copy（青）/ 内部（青・黒）/ 出口（緑）の三角が安定。
- 注意: 緑を増やしすぎると検出優位が落ちる → **1画面1つ**と「最終成果物のみ」が認知的ガードレール。

**推奨:** **案 G（紙+最終ファイル）** を定義文に採用。集合は E と同じ。印刷専用（P）は美しくても完了系統の学習コストで劣る。
