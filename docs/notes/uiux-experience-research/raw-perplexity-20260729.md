以下は、役員会に出すための **提案案** です。結論は出さず、総意と少数意見を分けて整理します。

## 提案の骨子

SUGUDASU は「登録不要・ブラウザ完結」の実務ツール群なので、UI は **完了の見え方を統一しつつ、処理の重さや出力先で例外を残す** 方針が妥当です。  
特に Copy-First / L1-L2-L3 / Calm UX は維持しつつ、今あるズレを「仕様の例外」と「実装の不統一」に分けて整理するのが役員会向けです。

## 総意として強い案

| 論点 | 提案 | ねらい | 根拠になる学習済みパターン / 物理メタファー |
|---|---|---|---|
| コピー成功 | 成功時は「コピーしました」+ emerald を標準に寄せる | 成功の即時認知を揃える | 物理リモコンの「押した感」、コピー機の完了ランプ |
| CTA階層 | 青を主CTA、緑を印刷/出力系に固定する | 入口と出口を混同させない | ATM の主要操作ボタンと紙 خروجし口の分離 |
| 完了モデル | Transform-Copy / Print-Finish / Bake-Download / Canvas-Copy / Continue-Later / Session-Ephemeral を画面ごとに明示する | “完了”の意味を出力先で変える | レジの「会計完了」とプリンタの「排紙完了」の違い |
| 体感SLA | 全ツール一律の高速契約感は作らず、pdf-fill など局所的に Calm UX を使う | 無理な統一で期待値を壊さない | エレベータの「待ち時間表示」は階層ごとに違う |
| DnD | `.sg-file-drop` は見た目だけでなく、必要なツールだけ JS で有効化を明示する | “ドロップできそう”の誤解を減らす | 物理の投入口に「使える口」と「飾り口」がある感覚 |

## 少数だが尖った意見

| 意見 | 立場 | 採否の扱い |
|---|---|---|
| 黒ボタンを帳票系で残す | 例外としてあり | 見た目の一貫性より、帳票/出力の“重み”を優先する考え方 |
| 緑を非印刷に回す | 条件付きであり | 印刷と画面完了を分けたい場合は有効。ただし説明が必要 |
| raw / alert / 独自トーストを完全排除しない | 例外容認 | 開発効率や古い導線の互換性を残す現実路線 |
| 実装の濃淡を“未完成”ではなく“段階的適用”と呼ぶ | 表現上の工夫としてあり | 仕様を壊さずに移行できる |

## 意図的に揃えないもの

| 揃えない対象 | 理由 |
|---|---|
| すべての画面を同じコピー緑ボタンにすること | 出力の意味が違うため、完了の種類を潰してしまう |
| ログイン必須への統一 | SUGUDASU の価値である即時性を壊す |
| 常時サーバー保存前提 | Session-Ephemeral や一時処理と相性が悪い |
| 流行グラデCTA | 実務ツールの認知を弱め、操作迷いを増やす |
| Platform SDK 先作り | 現状の課題は UI/文言/完了表現で、基盤刷新ではない |

## 役員会に出す一文

「SUGUDASU は、完了の種類を画面ごとに明示しながら、コピー成功・印刷・ダウンロード・一時処理のフィードバックを段階的に揃える。全体を同じ見た目に潰すのではなく、**完了モデルを統一し、例外を意図として残す** 方針を提案する。」
