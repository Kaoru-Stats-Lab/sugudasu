## 1. 五者の意見

### CTO

- **構造化したい。** 「黒=小操作」を契約に残すなら、**例外表か専用クラス**（例: `.sg-btn-tool` / `.sg-btn-ink`）がないと Agent が毎回迷う。
- 例外なしのまま「帳票は黒OK」と口頭運用すると Tech Adoption と同じ負債。
- **推奨:** 例外を認めるなら `product_voice: formal_document` かつ「S2 以下の道具操作」に限定した表を契約 §2 に書く。主完了（印刷）は緑のまま。

### CMO

- 帳票LP流入は「印刷・発行」がゴール。黒を青に揃えても CV は印刷緑に依存しがち。
- ただし **stamp「請求書へ」が黒**だと「次の課金導線」ではなく「道具の続き」に見え、ブランドの青主CTA学習と矛盾する。
- **推奨:** クロスツール handoff・共有URLは **青（L2）** に寄せ、行追加系だけ黒残し。

### CPO

- `formal_document` の「紙・印・確定」トーンで黒は物理メタファー（印鑑台・帳票ヘッダ）に合う。
- 一方、契約の「例外表なし」と実装が既に矛盾している（追認か矯正かの二択）。
- **推奨:** **小操作黒は追認** · **フル幅の黒CTAは追認しない**（青 or セカンダリ白枠へ）。stamp handoff は青。

### UIUX

- Consistency = 予測可能性。ユーザーは「青=進む / 緑=紙に出す / 黒=道具の細かい操作」と学習できるなら黒は残してよい。
- フル幅黒は「進む」に見える → **高さ・幅の規約**もセット（`text-xs` · 非フル幅 · 主CTAの下または脇）。
- **推奨:** 視覚階層ルールを DESIGN に1表追加。一括青寄せはしない。

### 認知科学

- 最初に invoice を見たユーザーが「SUGUDASUの主ボタンは黒」と学習し、normalize の青に移ると再学習コスト。
- 帳票クラスタ内だけ黒が続くならスキーマは局所安定する（ツール群のサブ文法）。
- **推奨:** **クラスタ例外**（formal_document の小操作のみ）を明示。ページ主ゴール（印刷）を黒にしない。

## 2. 総意（仮）と尖り

| 区分 | 内容 |
|------|------|
| **仮総意** | 黒を全廃して青一色にはしない。**小操作の黒は追認**。フル幅・「次のプロダクトへ」級は青（L2）へ是正 |
| **仮総意** | 契約に **例外表**（voice × スロット）を足す。「例外表なし」を削除 |
| **尖り①（Claude寄り）** | 帳票の主CTAまで黒追認 — 仮総意では不採択寄り（印刷緑・青主と三重化） |
| **尖り②** | 黒をセカンダリ専用クラスに格上げし、新規は `bg-slate-900` 生書き禁止 — CTO/UIUX が支持しやすい |
