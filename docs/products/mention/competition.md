# Mention Competition & White Space

**更新:** 2026-07-27  
**役割:** 市場 · 競合 · White Space · 「なぜ競合は同じものを作れないか」  
**非役割:** 実装仕様 · 価格表 · Extension 提出文面  
**使い方:** 「この機能、本当に必要？」のたびに本ファイルを開く。差別化の判断基準の正本。

---

## 1. 一文で言うと

競合は **見つけた言及を溜めて見せる**（Monitoring / Analytics / Dashboard）。

Mention は **今見ているページを終わらせる**（Current Context → Action → Done）。

同じ「言及」という言葉でも、Job が違う。

---

## 2. 市場の見え方（罠）

表面的に並べると Mention は次に見える。

| 誤ったカテゴリ | なぜ罠か |
|----------------|----------|
| Google口コミ返信ツール | Adapter の一つを Mission にしてしまう |
| ソーシャルリスニング | 監視・収集が本体になる |
| レピュテーション管理 SaaS | ダッシュボードと担当ワークフローが本体になる |

正しいカテゴリ:

> **Current Context Action Dispatcher**（ブラウザ拡張）

価格・GTM・機能追加は、このカテゴリを壊さないかを先に問う。

---

## 3. 競合マップ

### 3.1 監視・分析型（本命競合に見えて実は別 Job）

| 類型 | 例 | 売るもの | ユーザーの瞬間 |
|------|-----|----------|----------------|
| ソーシャルリスニング | Brand24 · Meltwater · 類似 SaaS | 言及の収集・感情・レポート | 「今週どうだった？」 |
| SEO / 言及・被リンク | Ahrefs 等の言及機能 | 発見・順位・リンク | 「どこに載った？」 |
| アラート | Google Alert | 通知メール | 「何かあった？」 |
| 国内レピュテーション | Canly 等 | 口コミ監視・店舗運用 | 「店舗の評価を管理」 |

共通構造:

```text
Crawl / Connect
  → Store
  → Dashboard / Alert
  → (あとから) 人が返信・共有
```

**終わらせる**のはプロダクトの外（別タブ · Slack · メモ帳）。

### 3.2 隣接だが違う

| 類型 | なぜ Mention ではないか |
|------|------------------------|
| ヘルプデスク / CRM | チケット・担当・期限が本体 |
| ソーシャル投稿スケジューラ | 発信が本体。受信の Done ではない |
| 汎用 AI サイドパネル | 文案生成・チャットが本体。Scenario→定型 Done ではない |

---

## 4. 競合が「その構造から抜け出せない」理由

機能の有無ではない。**ビジネスモデルと組織の慣性**である。

| 圧力 | 結果 |
|------|------|
| ARR / シート課金 | 「使い続け・見続け」が必要 → Dashboard が中心 |
| データ保管が価値の証明 | 保存量 · 期間 · ソース数がセールス資料になる |
| エンタープライズ営業 | 権限 · 監査 · レポート · ワークフロー承認が要件化 |
| 「全部見えてる感」 | 通知・感情分析・ランキングがロードマップの重力になる |
| 成功指標 | 滞在・DAU・レポート閲覧 → Done 速度と逆向き |

だから競合に「Side Panel で終わらせる」を足しても、本体は監視のまま残る。  
**削れない。** 削ると既存顧客・既存営業トークが壊れる。

Mention が最初から監視を持たないのは、後から足さないためではなく、**足したら自死する**からである（Constitution · Single Purpose）。

---

## 5. White Space

```text
User already found it
  （Chrome でページを開いている）
        ↓
  次の一手が欲しい
        ↓
  Reply / Share / Note / Done
        ↓
  元の仕事へ戻る
```

| White Space | Mention | 典型競合 |
|-------------|---------|----------|
| 入力 | Current Tab（User Opens First） | クロール · 連携 · アラート受信箱 |
| 画面 | Side Panel · Inbox のみ | Dashboard · レポート |
| 成果 | コピー / Webhook / Done | 「可視化された」状態 |
| データ | 端末内痕跡 · 非送信 | クラウド蓄積 |
| 進化方向 | Adapter 追加 · Done 速度 | Monitoring 深化 |

**見つけたあとの往復**（メモ帳 · Slack · 元ページ）を消す場所に、巨大 SaaS は座っていない。

---

## 6. 「なぜ競合は作れないか」（再掲・判断用）

1. **作れる技術**はある（拡張 + テンプレは難しくない）  
2. **作れないのは製品定義**である（監視をやめると会社が別物になる）  
3. Mention の防御は機能秘密ではなく **Non-Goals の徹底**  
4. 競合名でユーザーに語らない（CASE-2026-003）。語るのは Job と Done

「Brand24 より安い監視」は White Space ではない。罠である。

---

## 7. 機能追加ゲート（このファイルの運用）

新機能案が出たら、次を順に問う。

1. **競合と同じ重力か？**（溜める · 見せる · 通知する）→ なら Reject 候補  
2. **Current Context の Done が速くなるか？** → なければ不要  
3. **Adapter / Scenario / Action のどれか？** → Mission をプラットフォーム名にしない  
4. **Constitution（philosophy）と矛盾しないか？**

迷ったら: 監視に寄るなら切る。Done に寄るなら残す。

---

## 8. SUGUDASU との位置

既存 SUGUDASU ツールは日本実務の前工程に強い。  
Mention は **国を選ばないワークフロー**（見つける → 終わる）に寄せられる。

ただしカテゴリを「グローバル・リスニング SaaS」にすると、また監視の重力に吸い込まれる。  
グローバル化しても Job は変えない: **Find outside. Finish inside.**
