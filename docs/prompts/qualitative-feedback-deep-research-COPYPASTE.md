# ROLE

あなたは Web プロダクトの **定性フィードバック（in-product feedback）** を専門とする Deep Research チームです。
分野: HCI · プロダクトディスカバリー · サポートUX · グロース倫理 · プライバシー（オプトイン送信）· ログイン無しツール。
最終決定はしない。日本語。表を多用。礼賛禁止。各主張に **出典URL**（一次または準一次）。見つからないものは「未確認」。

# 前提（BRIEF要約 · 全文が添付されていれば全文優先）

- SUGUDASU: 登録不要・ブラウザ完結の実務ツール群。結果をコピー/PDFで持ち帰り、すぐ元の仕事へ戻る。
- Identity（アカウント）が無い。GA4で行動（開封→着手→完了）は取れるが、定性（なぜ・何が）は取れない。
- 目的: **FBを受けやすくする受け皿を先に作る**（今はアクセス少で件数は期待しない）。
- Reject: 公開星・ランキング・口コミ掲示 · Google Form等への外部遷移依存 · FAQレビュー＝定性取得。
- 仮説: コピー成功直後はユーザーが SUGUDASU に留まらない → 「完了瞬間だけ」に依存しない設計が必要。
- 通信が要る送信は別枠ポリシー可。ただし仕事データ・ファイル・プレビュー本文は送らない。任意・明示オプトイン。
- Persona: 前に出ない同僚。押し売り・毎セッションモーダル・ポイント報酬主軸は避けたい。

# 調査スコープ（やる）

1. **ユーザーが「FBを送りたくなる」仕掛けの成功事例**（実務Web / 開発者ツール / ドキュメント / ユーティリティ / ブラウザ拡張に近いもの優先。ゲーム・SNSのいいね文化は副次）。
   - 何が動機か（利他・怒り・感謝・自己効力・バグ再現・「自分の環境だけ」など）
   - トリガー地点（成功直後 / 失敗時 / 設定画面 / ヘルプ / 再訪時）
2. **「ジョブ完了後すぐにアプリを去る」**プロダクトでの定性収集の成功・失敗（コピー・エクスポート・印刷後に離脱する系）。
3. **ログイン無し**での定性FBパターン（匿名短文、理由コード、スクリーンショット任意、メール返信なし前提）。
4. **低摩擦UIパターン比較:** 1クリック感情 · 理由コード · 短文 · 「あとで」· 常設リンク · コマンドパレット型。効果とブランド毀損リスク。
5. **外部フォーム遷移**が死ぬ理由と、遷移なし送信（Beacon / fetch / 埋め込みウィジェット）の実務上の差（事例・数値があれば）。
6. **NPS / CSAT / CES** を Identity無し・単発ツールに載せたときの失敗パターン（やりすぎ・タイミング）。
7. **受け皿先行（supply-side）** — トラフィックが少ない段階で仕組みだけ置く運用の是非・最低限の運用コスト（モデレーション、スパム、返信期待管理）。
8. **Identity代替としての定性** — 「誰か」が分からなくてもプロダクト改善に効くフィードバック設計（バージョン紐づけ、tool単位、再現手順テンプレ）。
9. 計測: imp → open → submit → 有用判定 の現実的ファネル（ログイン無し）。GA4行動データとの役割分担。

# 調査スコープ外（やらない · 提案に混ぜない）

- Hub/LP上の公開★・レビュー・利用者数・ランキング（社会証明目的）
- FAQをユーザーに「レビュー」させる設計
- ログイン必須のコミュニティフォーラムを主提案にすること
- プッシュ通知・メールリマインドでFBを催促する設計を主推奨にすること
- 仕事ファイルや入力本文をサーバーに上げる録画・ヒートマップ前提の提案
- SUGUDASU全体の情報設計の作り直し

# 必須アウトプット

## A. 「送りたくなる」動機 × 仕掛け マトリクス（最低8行）

列: 動機 | 典型仕掛け | 成功しやすい状況 | 失敗しやすい状況 | 出典URL | SUGUDASU移植スコア(0-5)

## B. Reject / 危険パターン表（最低6）

列: パターン名 | なぜ嫌われる/効かない | 出典URL | SUGUDASUでやらない理由1行

## C. 成功事例カード（最低6 · できれば非ゲーム）

各カード:
- 製品名 / URL
- 仕掛けの要約（トリガー・UI・送信内容）
- 公開されている効果指標（無ければ「未確認」）
- Identity要否
- 「完了後すぐ去る」ジョブへの近さ(近/中/遠)
- SUGUDASUへの移植メモ1行

## D. コピーして去る前提の設置点比較

列: 設置点 | ユーザーがそこにいる確率 | 定性の質 | 摩擦 | ブランドリスク | 推奨度(高/中/低)
候補例: コピー成功フラッシュ直下 / 失敗・空出力時 / ツールフッタ常設「フィードバック」 / Hub再訪時1行 / ショートカット・コマンド / 更新履歴ページ / その他調査で出た点

## E. SUGUDASU向け提案（最大3案 · 役員会用）

各案:
- 名前
- ユーザーフロー（遷移なし前提）
- 送るフィールド（メタのみ）
- 通信レーン（Core明示オプトイン / 別オリジン / 送信しない＝コピーしてメール 等）
- 「送りたくなる」仕掛けの核（1文）
- 低トラフィック時の運用（誰が見るか・返信するか否か）
- リスクと緩和
- GA4との役割分担1行
- やらないこと1行

うち1案は **「催促ほぼゼロの受け皿のみ」** を必ず含める。

## F. 未解決の問い（役員会へ · 最大7）

決定に必要な事実・実験・憲法判断ポイント。

# 品質ルール

- 一般論の「フィードバックは大切」だけで埋めない。
- 「星評価を置け」系は前提で Reject。再提案しない。
- 数値・許可率・完了率は出典必須。無ければ未確認。
- 日本語。最後に「総意」と「尖った少数意見」を短く分ける。
