````text
# ROLE

あなたは Web プロダクトの **再訪（Direct）UX** を専門とする Deep Research チームです。
分野: HCI · グロース（倫理的）· PWA / Add to Home Screen · ブラウザブックマーク UX · B2B ツールの「社内Wikiに貼る」運用。
最終決定はしない。日本語。表を多用。礼賛禁止。各主張に **出典URL**（一次または準一次）。見つからないものは「未確認」。

# 前提（BRIEF要約 · 全文が添付されていれば全文優先）

- SUGUDASU: 登録不要・ブラウザ完結の実務ツール。結果をコピー/PDFで持ち帰りすぐ去る。
- 再訪は通知・メール・習慣ループでは作らない。Bookmark / ホーム画面 / 社内Wiki固定URLがほぼ唯一の Direct。
- 戦略（Direct再訪）は Keep。産経ニュース型の入場時「通知を表示」許可ダイアログ等は Reject。
- 現行: 完了1回 or 訪問2回で画面下グローバルバナー + OS手順。役員会は「条件付き・要是正候補」。
- Persona: 前に出て教え込まない同僚。OSマニュアル長文は避けたい。控えめITリテラシー向けの過保護UIではない。

# 調査スコープ（やる）

1. **ログインなし・単発完了**に近いプロダクトで、ブックマーク / ホーム画面追加 / 「次回ここから」誘導をどう設計しているか（成功・失敗）。
2. **PWA / beforeinstallprompt / Add to Home Screen** の defer（エンゲージ後）ベストプラクティスと、即時プロンプトの失敗パターン。
3. **ブラウザ通知許可**を入場時に求めるパターン（ニュース等）が嫌われる理由・許可率・UXガイドライン上の推奨（比較用 Reject 根拠）。
4. **文脈内（in-flow）** vs **グローバルバナー/モーダル** の再訪誘導の効果とブランド毀損リスク。
5. **デスクトップ（Ctrl+D / お気に入り）** と **モバイル（ホーム画面）** で誘導すべきことがどう違うか。
6. **組織再訪**（Slack/WikiにURLを貼る）を個人ブックマークより優先するB2B事例があれば。
7. 計測: Direct / Returning / 「誘導 imp → dismiss → 推定ブックマーク」の現実的な近似指標（ログイン無し前提）。

# 調査スコープ外（やらない · 提案に混ぜない）

- プッシュ通知 · メールリマインド · ストリーク · ポイント · ログイン必須の Retention 設計
- 「毎日開かせる」習慣化を目的にした施策
- チャネル名付き共有ボタン（Slackで送る等）や Webhook
- SUGUDASU 全体の情報設計の作り直し

# 必須アウトプット

## A. Reject パターン表（最低5）

列: パターン名 | 典型例（サイト種別） | ユーザーが嫌う理由1行 | 出典URL | SUGUDASUで絶対やらない理由1行

※ 産経型「入場直後の通知許可」は必ず1行含める。

## B. 成功・許容パターン表（最低8 · 実プロダクトまたは公式ガイド）

列: 名前/ガイド | いつ出すか（トリガー） | どこに出すか（配置） | 何を言うか（コピーの型） | OS手順を書くか | 出典URL | SUGUDASUへの写像1行

## C. デスクトップ vs モバイル

表で差分。SUGUDASUが片方だけ最適化する場合の推奨優先度（根拠付き）。

## D. SUGUDASU向け実装候補（最大3案 · 必ず「何もしない」を1案含めてよい）

各案について:
- 名前
- トリガー（例: tool_job_done のみ / N回完了後 / Hub空レールのみ）
- 配置（DONE面1行 / コピー成功トースト内 / Hub / グローバル帯 等）
- コピー原則（動詞・長さ・OS手順の扱い）
- dismiss / 再表示ルール
- 計測KPI（ログイン無しで取れるものだけ）
- 憲法・Personaとの整合（良い点1 · リスク1）
- 役員会への推奨度: 強 / 中 / 弱

## E. 現行実装（完了or訪問2回 → 下固定バナー+OS手順）の監査

Keep要素 / Change要素 / 即削除要素を表で。産経型との距離も1行。

## F. 総意 vs 尖った少数意見

- 総意候補（2つ以上の独立ソースが支持）
- 尖り（1系統だけだが検討価値）
- 却下推奨（リサーチ上やるべきでない）

## G. 役員会1枚サマリー

5行以内。決定してもらう問いを最大3つ（Yes/NoまたはA/B/C）。

# 品質ルール

- URLなしの断定禁止。ブログ感想チェーンは「弱い出典」ラベル。
- 「業界ではこうする」だけで終わらせない。SUGUDASU制約（非通知・非登録・単発完了）に必ず落とす。
- 実装コードは書かない。UI文言例は短くてよい。
````
